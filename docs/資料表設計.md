# 個人記帳本資料表設計規格書 (Supabase PostgreSQL)

本文件為個人記帳系統的關聯式資料庫結構設計規格，底層資料庫為託管於 Supabase 的 PostgreSQL。本設計旨在精確支援個人的四本核心冊子（**入帳**、**花費**、**投資**、**發票**）以及資產帳戶移轉與兌獎機制，並符合高可靠性財務資料建模標準。

---

## 壹、核心設計準則與約束規範

1. **主鍵策略**：
   - 全系統所有資料表一律採用「資料庫自動產生、建立後不可修改的 64 位元整數」作為主鍵（`id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`）。
   - 業務自然鍵（如發票號碼、標的代號等）一律退為業務屬性並建立 `UNIQUE` 約束，絕不做為物理主鍵。

2. **外鍵參照與連帶行為**：
   - 遵循嚴格的資料完整性：**父列若仍被其他資料列參照，一律禁止刪除**（PostgreSQL 預設行為 `ON DELETE RESTRICT` / `NO ACTION`）。
   - **全系統唯一的級聯刪除例外**：僅有「發票品項（`invoice_item`）」在父表「統一發票（`invoice`）」被刪除時，允許隨著發票一起連帶消失（`ON DELETE CASCADE`）。

3. **審計時間戳記（Audit Timestamps）**：
   - 每張表皆強制包含 `created_at` 與 `updated_at` 兩個 `TIMESTAMPTZ` 欄位。
   - `created_at`：在資料列插入（INSERT）時，由資料庫預設填入 UTC 時間（`DEFAULT timezone('utc', now())`）。
   - `updated_at`：在資料列建立時填入當前時間，後續資料列變更（UPDATE）時，**由應用程式（API）負責傳入更新當下的 UTC 時間寫入**，不透過資料庫自動觸發器隱式變更，保持呼叫端的確定性。

4. **貨幣、金額與匯率規則**：
   - 幣別代碼（`currency`）一律採用 ISO 4217 標準之 3 碼大寫英文字元（如 `TWD`, `USD`, `JPY`）。
   - 交易金額使用具備小數精度的數字（`NUMERIC(16, 2)` 或 `NUMERIC(16, 4)`），嚴禁使用浮點數（FLOAT / DOUBLE）。
   - 每筆涉及資金的交易皆留存換算成新台幣之匯率欄位（`exchange_rate_to_twd`），支援外幣記帳：
     - **新台幣規則**：幣別為 `TWD` 時，匯率固定為 `1.000000`。
     - **外幣規則**：幣別非 `TWD` 時，匯率必須大於 `0`。
     - 此規則在資料庫層以 `CHECK` 約束強制保證。

5. **不儲存可修改的衍生命題**：
   - 帳戶當前餘額、投資標的之持有股數與平均持有成本，均**不設計成可任意 UPDATE 的實體欄位**，避免併發修改衝突或交易失步。
   - 上述數值一律由基礎交易記錄按嚴格公式動態聚合或依時序推導計算得出（見本規格書「肆、衍生數值計算規範」）。

6. **約束分層與檢查職責**：
   - **資料庫約束**：資料格式（正規表示式）、欄位依賴性、非負檢核、唯一性、外鍵關聯等規則，一律在 PostgreSQL 層以 `CHECK`、`UNIQUE`、`FOREIGN KEY` 予以鎖死。
   - **API 寫入前檢查**：跨列時序狀態檢驗（例如「賣出股數不得大於現有持股庫存」）明確標註為「由 API 在交易事務（Transaction）內鎖定並檢查」。

## 貳、資料表詳細規格

全系統共規劃 10 張資料表，劃分為四個核心領域模組：
1. **帳戶與資金移轉模組**：`account`、`account_transfer`
2. **收支與分類模組**：`income_category`、`expense_category`、`income`、`expense`
3. **統一發票與開獎模組**：`invoice`、`invoice_item`、`invoice_prize_rule`、`invoice_lottery_draw`
4. **投資交易模組**：`investment_asset`、`investment_transaction`

---

### 一、帳戶與資金移轉模組

#### 1. 帳戶表 (`account`)

- **表在記什麼**：
  記錄所有承載資金的實體或虛擬錢包，包含現金、銀行活存帳戶、信用卡與證券商交割帳戶。
- **為什麼單獨成表**：
  資金的進出、流動與結算必須錨定於實體資金載體。若將帳戶屬性（如帳戶別、計價幣別）混雜於流水帳，會導致帳戶定義重複、難以實施轉帳與餘額對帳。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `name` | `VARCHAR(50)` | 必填 | 唯一 (UNIQUE) | 帳戶名稱（如：台新 Richart、中信交割戶、錢包現金） |
| `account_type` | `VARCHAR(20)` | 必填 | 一般 | 帳戶類型：`cash`、`bank`、`credit_card`、`brokerage_settlement` |
| `currency` | `CHAR(3)` | 必填 | 一般 | 帳戶基準幣別，預設為 `TWD` |
| `initial_balance` | `NUMERIC(16, 2)` | 必填 | 一般 | 建立帳戶時的初始基底餘額，預設為 `0.00` |
| `is_active` | `BOOLEAN` | 必填 | 一般 | 帳戶啟用狀態，預設為 `true` |
| `note` | `TEXT` | 可空 | 一般 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `account_pkey`: PRIMARY KEY (`id`)
  - `account_name_key`: UNIQUE (`name`)
  - `chk_account_type`: CHECK (`account_type IN ('cash', 'bank', 'credit_card', 'brokerage_settlement')`)
  - `chk_account_currency`: CHECK (`currency ~ '^[A-Z]{3}$'`)
- **API 寫入前檢查**：
  - 停用帳戶（`is_active = false`）前，需確認該帳戶當前動態算出的餘額為 0，且無未結清之信用卡花費款項。

---

#### 2. 帳戶移轉表 (`account_transfer`)

- **表在記什麼**：
  記錄同一使用者在不同內部帳戶之間的資金轉移，例如從銀行提領現金、從銀行撥款至證券交割戶、或從銀行帳戶扣繳信用卡費。
- **為什麼單獨成表**：
  移轉只是資金在資產內部的位置挪動，**既不是收入（入帳），也不是支出（花費）**。若將移轉拆開寫成一筆花費加一筆入帳，會虛增當月收支總額並扭曲財務報表；單獨成表能嚴格保障出入帳戶的雙向原子性（Atomicity）。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `from_account_id` | `BIGINT` | 必填 | 一般 (FK) | 轉出帳戶，外鍵指向 `account(id)`，參照時禁止刪除 |
| `to_account_id` | `BIGINT` | 必填 | 一般 (FK) | 轉入帳戶，外鍵指向 `account(id)`，參照時禁止刪除 |
| `transfer_date` | `TIMESTAMPTZ` | 必填 | 一般 | 轉帳生效時間 |
| `out_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 轉出金額（轉出帳戶幣別），必須大於 0 |
| `in_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 實際轉入金額（轉入帳戶幣別），必須大於 0 |
| `fee_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 轉帳手續費（自轉出帳戶扣除），預設 `0.00`，大於等於 0 |
| `currency` | `CHAR(3)` | 必填 | 一般 | 結算參考幣別（通常為轉出帳戶幣別） |
| `exchange_rate_to_twd` | `NUMERIC(12, 6)` | 必填 | 一般 | 換算台幣匯率（台幣為 1.0，外幣大於 0） |
| `note` | `TEXT` | 可空 | 一般 | 轉帳備註 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `account_transfer_pkey`: PRIMARY KEY (`id`)
  - `fk_transfer_from_account`: FOREIGN KEY (`from_account_id`) REFERENCES `account`(`id`) ON DELETE RESTRICT
  - `fk_transfer_to_account`: FOREIGN KEY (`to_account_id`) REFERENCES `account`(`id`) ON DELETE RESTRICT
  - `chk_transfer_different_accounts`: CHECK (`from_account_id <> to_account_id`)
  - `chk_transfer_amounts_positive`: CHECK (`out_amount > 0 AND in_amount > 0 AND fee_amount >= 0`)
  - `chk_transfer_exchange_rate`: CHECK ((`currency = 'TWD'` AND `exchange_rate_to_twd = 1.0`) OR (`currency <> 'TWD'` AND `exchange_rate_to_twd > 0`))
- **API 寫入前檢查**：
  - 轉出帳戶與轉入帳戶必須皆處於啟用狀態（`is_active = true`）。
  - 當轉出帳戶非信用卡時，需檢查轉出帳戶可用餘額是否足夠支付 `out_amount + fee_amount`。

### 二、收支與分類模組

依據業務約束，**入帳與花費的分類必須分開，名稱各自不能重複**，因此分別建立專屬分類表。

#### 3. 入帳分類表 (`income_category`)

- **表在記什麼**：
  記錄所有錢進來時的歸類標籤（如：薪資、年終獎金、利息、退款、統一發票中獎、股票現金股利、減資退回現金等）。
- **為什麼單獨成表**：
  入帳與花費本質不同，分類維度相互獨立；單獨成表可防止入帳誤選花費類別（如「伙食費」），並確保入帳分類名稱在自身命名空間具唯一性。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `name` | `VARCHAR(50)` | 必填 | 唯一 (UNIQUE) | 入帳分類名稱，不能重複 |
| `description` | `TEXT` | 可空 | 一般 | 分類描述 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `income_category_pkey`: PRIMARY KEY (`id`)
  - `income_category_name_key`: UNIQUE (`name`)
- **API 寫入前檢查**：
  - 名稱兩端禁止包含空白字元，寫入前需進行 trim 處理。

---

#### 4. 花費分類表 (`expense_category`)

- **表在記什麼**：
  記錄所有錢出去時的歸類標籤（如：飲食、交通、生活用品、房租、娛樂、醫療、保險等）。
- **為什麼單獨成表**：
  獨立定義支出屬性，與入帳分類徹底解耦，確保花費分類名稱在自身命名空間內獨立唯一。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `name` | `VARCHAR(50)` | 必填 | 唯一 (UNIQUE) | 花費分類名稱，不能重複 |
| `description` | `TEXT` | 可空 | 一般 | 分類描述 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `expense_category_pkey`: PRIMARY KEY (`id`)
  - `expense_category_name_key`: UNIQUE (`name`)
- **API 寫入前檢查**：
  - 名稱兩端禁止包含空白字元，寫入前需進行 trim 處理。

---

#### 5. 入帳表記錄表 (`income`)

- **表在記什麼**：
  記錄每一筆個人實質資金流入的明細帳，包括外部收入、發票中獎獎金、股票現金股利與減資退回款項。
- **為什麼單獨成表**：
  入帳代表個人實質淨資產增加，其資訊重點在於資金來源、入帳帳戶與關聯的法定或投資事件（如發票中獎或股票分紅）。
- **業務規則串接**：
  - 一張發票最多只能對應一筆中獎入帳：透過 `invoice_id` 的 `UNIQUE` 約束達成。
  - 一筆投資交易最多只能對應一筆現金收入：透過 `investment_transaction_id` 的 `UNIQUE` 約束達成。
  - 一筆入帳不能同時參照發票中獎與投資交易，由 `CHECK` 約束強制互斥或純外部收入。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `account_id` | `BIGINT` | 必填 | 一般 (FK) | 收款帳戶，外鍵指向 `account(id)`，參照時禁止刪除 |
| `category_id` | `BIGINT` | 必填 | 一般 (FK) | 入帳分類，外鍵指向 `income_category(id)`，參照時禁止刪除 |
| `invoice_id` | `BIGINT` | 可空 | 唯一 (UNIQUE, FK) | 關聯中獎發票，指向 `invoice(id)`，一張發票最多一筆入帳 |
| `investment_transaction_id` | `BIGINT` | 可空 | 唯一 (UNIQUE, FK) | 關聯投資交易（股利/減資），指向 `investment_transaction(id)`，一筆交易最多一筆入帳 |
| `income_date` | `TIMESTAMPTZ` | 必填 | 一般 | 資金入帳生效時間 |
| `original_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 原幣金額，必須大於 0 |
| `currency` | `CHAR(3)` | 必填 | 一般 | 原幣幣別（如 TWD, USD） |
| `exchange_rate_to_twd` | `NUMERIC(12, 6)` | 必填 | 一般 | 換算台幣匯率（TWD 為 1.0，外幣大於 0） |
| `twd_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 折合台幣金額，等於 `original_amount * exchange_rate_to_twd` |
| `source` | `VARCHAR(100)` | 可空 | 一般 | 資金來源摘要（如：某某公司薪資、財政部印刷廠） |
| `note` | `TEXT` | 可空 | 一般 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `income_pkey`: PRIMARY KEY (`id`)
  - `fk_income_account`: FOREIGN KEY (`account_id`) REFERENCES `account`(`id`) ON DELETE RESTRICT
  - `fk_income_category`: FOREIGN KEY (`category_id`) REFERENCES `income_category`(`id`) ON DELETE RESTRICT
  - `fk_income_invoice`: FOREIGN KEY (`invoice_id`) REFERENCES `invoice`(`id`) ON DELETE RESTRICT
  - `fk_income_investment_tx`: FOREIGN KEY (`investment_transaction_id`) REFERENCES `investment_transaction`(`id`) ON DELETE RESTRICT
  - `income_invoice_id_key`: UNIQUE (`invoice_id`)
  - `income_investment_transaction_id_key`: UNIQUE (`investment_transaction_id`)
  - `chk_income_original_amount_positive`: CHECK (`original_amount > 0`)
  - `chk_income_twd_amount_positive`: CHECK (`twd_amount > 0`)
  - `chk_income_exchange_rate`: CHECK ((`currency = 'TWD'` AND `exchange_rate_to_twd = 1.0`) OR (`currency <> 'TWD'` AND `exchange_rate_to_twd > 0`))
  - `chk_income_exclusive_source`: CHECK (`NOT (invoice_id IS NOT NULL AND investment_transaction_id IS NOT NULL)`)
- **API 寫入前檢查**：
  - 當 `invoice_id` 不為空時，API 必須檢核該發票在 `invoice` 表中已確認中獎，且 `original_amount` 等於其對應之開獎獎項金額。
  - 當 `investment_transaction_id` 不為空時，API 必須檢核該筆投資交易型態為 `cash_dividend`（現金股利）或 `capital_reduction`（減資），且入帳金額必須符合交易紀錄之實收總額。
  - 檢驗 `twd_amount` 之四捨五入計算是否正確（`ROUND(original_amount * exchange_rate_to_twd, 2)`）。

#### 6. 花費表記錄表 (`expense`)

- **表在記什麼**：
  記錄每一筆錢出去的流水明細帳，包括現金支付、銀行轉帳消費與信用卡刷卡支出。
- **為什麼單獨成表**：
  花費代表資產的實質消耗。本表支援信用卡消費的生命週期（消費日與信用卡實際扣款日分開），並支援與統一發票多對一的彈性勾稽。
- **業務規則串接**：
  - **消費日與扣款日不同**：提供 `expense_date`（消費日）與 `settlement_date`（扣款結算日）。現金或活儲消費時兩者同日；信用卡刷卡時，消費日為當天，扣款日可在未來信用卡結算繳款時補登或指定。
  - **發票對應**：花費外鍵 `invoice_id` 為一般外鍵（無唯一性約束），因此「一張發票可以對到多筆花費」。多筆花費合計不必等於發票金額（例如發票中包含代購品項、不報銷項目，或僅部分列入花費）。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `account_id` | `BIGINT` | 必填 | 一般 (FK) | 支付/扣款帳戶，外鍵指向 `account(id)`，參照時禁止刪除 |
| `category_id` | `BIGINT` | 必填 | 一般 (FK) | 花費分類，外鍵指向 `expense_category(id)`，參照時禁止刪除 |
| `invoice_id` | `BIGINT` | 可空 | 一般 (FK) | 關聯之統一發票，指向 `invoice(id)`，允許多對一 |
| `expense_date` | `TIMESTAMPTZ` | 必填 | 一般 | 實際消費發生日期時間 |
| `settlement_date` | `TIMESTAMPTZ` | 可空 | 一般 | 扣款或信用卡結算繳款日（可不同於消費日） |
| `original_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 原幣花費金額，必須大於 0 |
| `currency` | `CHAR(3)` | 必填 | 一般 | 原幣幣別（如 TWD, JPY） |
| `exchange_rate_to_twd` | `NUMERIC(12, 6)` | 必填 | 一般 | 換算台幣匯率（TWD 為 1.0，外幣大於 0） |
| `twd_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 折合台幣金額，等於 `original_amount * exchange_rate_to_twd` |
| `merchant_name` | `VARCHAR(100)` | 可空 | 一般 | 消費店家或商家名稱 |
| `note` | `TEXT` | 可空 | 一般 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `expense_pkey`: PRIMARY KEY (`id`)
  - `fk_expense_account`: FOREIGN KEY (`account_id`) REFERENCES `account`(`id`) ON DELETE RESTRICT
  - `fk_expense_category`: FOREIGN KEY (`category_id`) REFERENCES `expense_category`(`id`) ON DELETE RESTRICT
  - `fk_expense_invoice`: FOREIGN KEY (`invoice_id`) REFERENCES `invoice`(`id`) ON DELETE RESTRICT
  - `chk_expense_original_amount_positive`: CHECK (`original_amount > 0`)
  - `chk_expense_twd_amount_positive`: CHECK (`twd_amount > 0`)
  - `chk_expense_exchange_rate`: CHECK ((`currency = 'TWD'` AND `exchange_rate_to_twd = 1.0`) OR (`currency <> 'TWD'` AND `exchange_rate_to_twd > 0`))
- **API 寫入前檢查**：
  - 若帳戶類型為一般現金或銀行帳戶，預設將 `settlement_date` 自動帶入為 `expense_date`；若帳戶類型為 `credit_card`，則允許先保留 `settlement_date` 為空，待收到帳單對帳後填寫。
  - 當存在關聯 `invoice_id` 時，API 不強制檢查金額相等（允許小於或大於發票總額）。

### 三、統一發票與開獎模組

#### 7. 統一發票表 (`invoice`)

- **表在記什麼**：
  記錄在台灣消費取得的統一發票主檔憑證，包含號碼、開立日、期別、總金額、賣方資訊、隨機碼及中獎註記。
- **為什麼單獨成表**：
  發票是法律與稅務實體憑證，其生命週期包含品項留底、每期對獎與領獎入帳，與花費明細並非一對一等價關係。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `invoice_number` | `CHAR(10)` | 必填 | 複合唯一 | 統一發票號碼：2 碼大寫英文字母 + 8 碼數字 |
| `period` | `CHAR(7)` | 必填 | 複合唯一 | 發票期別（格式 `YYYY-MM`，如 `2026-01` 代表 1-2 月期） |
| `invoice_date` | `TIMESTAMPTZ` | 必填 | 一般 | 發票開立日期時間 |
| `total_amount` | `NUMERIC(12, 2)` | 必填 | 一般 | 發票開立總金額，大於等於 0 |
| `seller_tax_id` | `CHAR(8)` | 可空 | 一般 | 賣方統一編號（8 位數字） |
| `seller_name` | `VARCHAR(100)` | 可空 | 一般 | 賣方商家名稱 |
| `buyer_tax_id` | `CHAR(8)` | 可空 | 一般 | 買方統一編號（個人打統編或報帳留底，8 位數字） |
| `random_code` | `CHAR(4)` | 可空 | 一般 | 發票隨機碼（4 位數字） |
| `winning_prize_id` | `BIGINT` | 可空 | 一般 (FK) | 中獎獎項，外鍵指向 `invoice_prize_rule(id)`，參照時禁止刪除 |
| `note` | `TEXT` | 可空 | 一般 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `invoice_pkey`: PRIMARY KEY (`id`)
  - `invoice_period_number_key`: UNIQUE (`period`, `invoice_number`)
  - `fk_invoice_winning_prize`: FOREIGN KEY (`winning_prize_id`) REFERENCES `invoice_prize_rule`(`id`) ON DELETE RESTRICT
  - `chk_invoice_number_format`: CHECK (`invoice_number ~ '^[A-Z]{2}[0-9]{8}$'`)
  - `chk_invoice_period_format`: CHECK (`period ~ '^[0-9]{4}-(01|03|05|07|09|11)$'`)
  - `chk_invoice_total_amount`: CHECK (`total_amount >= 0`)
  - `chk_invoice_seller_tax_id`: CHECK (`seller_tax_id IS NULL OR seller_tax_id ~ '^[0-9]{8}$'`)
  - `chk_invoice_buyer_tax_id`: CHECK (`buyer_tax_id IS NULL OR buyer_tax_id ~ '^[0-9]{8}$'`)
  - `chk_invoice_random_code`: CHECK (`random_code IS NULL OR random_code ~ '^[0-9]{4}$'`)
- **期別（`period`）由開立日（`invoice_date`）決定的業務規則**：
  - 台灣統一發票每兩個月為一期，單數月為該期起始月：
    - 01 月與 02 月開立 $\rightarrow$ 該年 `01` 期（儲存為 `YYYY-01`）
    - 03 月與 04 月開立 $\rightarrow$ 該年 `03` 期（儲存為 `YYYY-03`）
    - 05 月與 06 月開立 $\rightarrow$ 該年 `05` 期（儲存為 `YYYY-05`）
    - 07 月與 08 月開立 $\rightarrow$ 該年 `07` 期（儲存為 `YYYY-07`）
    - 09 月與 10 月開立 $\rightarrow$ 該年 `09` 期（儲存為 `YYYY-09`）
    - 11 月與 12 月開立 $\rightarrow$ 該年 `11` 期（儲存為 `YYYY-11`）
  - **由 API 在寫入前檢查與計算**：API 於寫入發票時，依據傳入的 `invoice_date` 取出西元年份與月份，以計算公式算出起始雙數月並填入 `period` 欄位（例如 2026 年 4 月 15 日對應 `2026-03` 期），並由 CHECK 約束驗證格式合規。

### 四、投資交易模組

#### 12. 投資交易表 (`investment_transaction`)

- **表在記什麼**：
  記錄一檔標的與每一筆實際發生的金融交易，涵蓋所有權益變動事件與資金扣繳記錄。
- **為什麼單獨成表**：
  投資交易具備高度專業屬性（成交股數、成交單價、手續費、證券交易稅、權益調整比率），無法與一般日常花費合併；單獨成表可建立完整的時間序列帳簿，供精確計算庫存股數與加權成本。
- **交易種類定義**（完全涵蓋需求所列 8 種型態）：
  1. `buy`（買進）：股數增加，支出現金（成交金額 + 手續費）。
  2. `sell`（賣出）：股數減少，收取現金（成交金額 - 手續費 - 證交稅）。
  3. `cash_dividend`（現金股利）：股數不變，收取現金分紅。
  4. `stock_dividend`（配股）：股數增加，無現金流入（分配股票股利）。
  5. `dividend_reinvestment`（股息再投入）：收到股息即刻以當期價格買入對應股數，股數增加，現金流兩相沖銷。
  6. `stock_split`（分割）：股數按比例放大，每股面值降低，無現金流（如 1 股拆為 2 股）。
  7. `stock_reverse_split`（合併/反分割）：股數按比例縮小，無現金流（如 5 股併為 1 股）。
  8. `capital_reduction`（減資）：股數按減資比率縮減；若為「現金減資」則退回現金款項。
- **欄位明細規格**：

| 欄位名稱 | 型態 | 必填/可空 | 唯一性 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | 唯一 (PK) | 主鍵，資料庫自動產生，不可改 |
| `asset_id` | `BIGINT` | 必填 | 一般 (FK) | 投資標的，指向 `investment_asset(id)`，參照時禁止刪除 |
| `settlement_account_id` | `BIGINT` | 可空 | 一般 (FK) | 資金交割帳戶，指向 `account(id)`，參照時禁止刪除 |
| `transaction_type` | `VARCHAR(30)` | 必填 | 一般 | 交易型態（見上方 8 種類型 CHECK 約束） |
| `transaction_date` | `TIMESTAMPTZ` | 必填 | 一般 | 交易發生或除權息生效日期時間 |
| `shares_delta` | `NUMERIC(16, 4)` | 必填 | 一般 | **股數淨變動量**（買進/配股/再投入為正；賣出/合併/減資為負；現金股利為 0） |
| `unit_price` | `NUMERIC(16, 4)` | 可空 | 一般 | 成交單價（買進、賣出、股息再投入時必填，配股/分割可為空） |
| `total_cash_amount` | `NUMERIC(16, 2)` | 必填 | 一般 | 現金結算總金額（不含手續費與稅，無現金流事件為 0） |
| `fee` | `NUMERIC(12, 2)` | 必填 | 一般 | 券商手續費，預設 `0.00`，大於等於 0 |
| `tax` | `NUMERIC(12, 2)` | 必填 | 一般 | 證券交易稅，預設 `0.00`，大於等於 0 |
| `currency` | `CHAR(3)` | 必填 | 一般 | 交易計價幣別 |
| `exchange_rate_to_twd` | `NUMERIC(12, 6)` | 必填 | 一般 | 換算台幣匯率（TWD 為 1.0，外幣大於 0） |
| `split_ratio` | `NUMERIC(12, 6)` | 可空 | 一般 | 分割/合併或減資比率（如 2:1 分割填 2.0，1:5 反分割填 0.2） |
| `note` | `TEXT` | 可空 | 一般 | 交易備註 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 一般 | 建立時間，資料庫預設填入 UTC |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 一般 | 最後更新時間，由程式寫入 UTC |

- **PostgreSQL 約束定義**：
  - `investment_transaction_pkey`: PRIMARY KEY (`id`)
  - `fk_investment_tx_asset`: FOREIGN KEY (`asset_id`) REFERENCES `investment_asset`(`id`) ON DELETE RESTRICT
  - `fk_investment_tx_settlement_account`: FOREIGN KEY (`settlement_account_id`) REFERENCES `account`(`id`) ON DELETE RESTRICT
  - `chk_investment_tx_type`: CHECK (`transaction_type IN ('buy', 'sell', 'cash_dividend', 'stock_dividend', 'dividend_reinvestment', 'stock_split', 'stock_reverse_split', 'capital_reduction')`)
  - `chk_investment_tx_fees`: CHECK (`fee >= 0 AND tax >= 0 AND total_cash_amount >= 0`)
  - `chk_investment_tx_exchange_rate`: CHECK ((`currency = 'TWD'` AND `exchange_rate_to_twd = 1.0`) OR (`currency <> 'TWD'` AND `exchange_rate_to_twd > 0`))
  - `chk_investment_tx_shares_rule`: CHECK (
      (`transaction_type = 'buy'` AND `shares_delta > 0`) OR
      (`transaction_type = 'sell'` AND `shares_delta < 0`) OR
      (`transaction_type = 'cash_dividend'` AND `shares_delta = 0`) OR
      (`transaction_type = 'stock_dividend'` AND `shares_delta > 0`) OR
      (`transaction_type = 'dividend_reinvestment'` AND `shares_delta > 0`) OR
      (`transaction_type = 'stock_split'` AND `shares_delta > 0`) OR
      (`transaction_type = 'stock_reverse_split'` AND `shares_delta < 0`) OR
      (`transaction_type = 'capital_reduction'` AND `shares_delta < 0`)
    )
- **API 寫入前檢查**：
  - **賣出不得使持有小於 0 檢查（核心規則）**：
    - 因庫存股數為跨列聚合結果，無法以單列 CHECK 約束限制，**明確由 API 在寫入前檢查**。
    - API 於執行賣出、反分割或減資時，必須在資料庫 Transaction 內針對該標的鎖定相關交易列（`SELECT ... FOR UPDATE`），依時序累計截至當前交易日之持有股數：
      $$\text{現有持有股數} = \sum_{t \le \text{當前交易日}} \text{shares\_delta}$$
    - 若 `現有持有股數 + 變動股數 (負值) < 0`，API 必須拒絕寫入，並回傳「庫存不足，不得超賣」之業務異常。
  - **現金入帳勾稽檢查**：
    - 當交易類型為 `cash_dividend` 或現金減資的 `capital_reduction` 且伴隨實質退款至交割戶時，API 同步在 `income` 表建立一筆入帳資料，並將 `income.investment_transaction_id` 指向該筆交易 ID。入帳表端具備 `UNIQUE` 約束，保證一筆交易絕對最多只能產出一筆入帳。

## 肆、衍生數值計算規範（不實體儲存欄位）

為維護資料最高一致性，系統嚴禁將「帳戶餘額」、「持有股數」及「平均成本」儲存為一般可隨意被 UPDATE 的欄位。以下明定其數學推導與查詢聚合規則：

### 一、帳戶當前餘額（Account Balance）

一個帳戶在特定時間點的餘額，由以下 4 類資料列之和與差動態算出：

$$\text{帳戶當前餘額} = \text{initial\_balance} + \text{總入帳金額} - \text{總花費金額} + \text{總移轉轉入金額} - \text{總移轉轉出金額}$$

具體參與計算之欄位與條件：
1. **基底餘額**：`account.initial_balance`。
2. **入帳增加**（$+$）：`income.original_amount`，條件為 `income.account_id = account.id`。
   - 註：若發票中獎、股票現金股利、減資現金退款已依照業務規則寫入 `income` 表並指定該帳戶，則自動涵蓋在入帳增加項目中，無需重複計算。
3. **花費減少**（$-$）：`expense.original_amount`，條件為 `expense.account_id = account.id`。
   - 註：信用卡帳戶之餘額表現通常為負值或累計未結款項；當以銀行帳戶轉帳繳納信用卡費時，透過 `account_transfer` 從銀行轉入信用卡，即可沖銷信用卡負額。
4. **移轉轉入**（$+$）：`account_transfer.in_amount`，條件為 `account_transfer.to_account_id = account.id`。
5. **移轉轉出**（$-$）：`account_transfer.out_amount + account_transfer.fee_amount`，條件為 `account_transfer.from_account_id = account.id`（包含轉出金額與自轉出帳戶扣除之手續費）。
6. **投資交割現金流直接扣繳**（若投資交易直接自交割戶扣款且未列入一般收支時）：
   - 買進（$-$）：`total_cash_amount + fee`。
   - 賣出（$+$）：`total_cash_amount - fee - tax`。

---

### 二、投資持有股數（Holding Shares）

特定投資標的（`asset_id`）當前所持有的股數，由該標的下所有歷史投資交易的淨股數變動值直接加總求得：

$$\text{當前持有股數} = \sum_{\text{所有該標的交易}} \text{shares\_delta}$$

- **買進 (`buy`)**：$\text{shares\_delta} > 0$（持股增加）。
- **賣出 (`sell`)**：$\text{shares\_delta} < 0$（持股減少）。
- **配股 (`stock_dividend`)**：$\text{shares\_delta} > 0$（持股增加）。
- **股息再投入 (`dividend_reinvestment`)**：$\text{shares\_delta} > 0$（持股增加）。
- **分割 (`stock_split`)**：$\text{shares\_delta} = \text{原持股} \times (\text{split\_ratio} - 1) > 0$（持股增加）。
- **合併 (`stock_reverse_split`)**：$\text{shares\_delta} = \text{原持股} \times (\text{split\_ratio} - 1) < 0$（持股減少）。
- **減資 (`capital_reduction`)**：$\text{shares\_delta} < 0$（依減資比例縮減股數）。
- **現金股利 (`cash_dividend`)**：$\text{shares\_delta} = 0$（持股不變）。

---

### 三、平均持有成本（Average Cost）

採用金融業界通用的**加權平均成本法（Weighted Average Cost Basis）**，按交易發生時間（`transaction_date`）由遠至近依序推導。設第 $k$ 筆交易後之「總庫存成本」為 $C_k$、「總持有股數」為 $S_k$：

1. **買進 (`buy`)**：
   $$S_k = S_{k-1} + \text{買進股數}$$
   $$C_k = C_{k-1} + (\text{成交金額} + \text{手續費})$$
   $$\text{每股平均成本 } P_k = \frac{C_k}{S_k}$$
2. **股息再投入 (`dividend_reinvestment`)**：
   $$S_k = S_{k-1} + \text{再投入增加股數}$$
   $$C_k = C_{k-1} + \text{再投入總金額}$$
   $$\text{每股平均成本 } P_k = \frac{C_k}{S_k}$$
3. **配股 / 股票分割 / 反分割合併**（無現金變動）：
   $$S_k = S_{k-1} + \text{shares\_delta}$$
   $$C_k = C_{k-1} \quad (\text{總持有成本保持不變})$$
   $$\text{每股平均成本重新稀釋/濃縮為 } P_k = \frac{C_k}{S_k}$$
4. **現金減資 (`capital_reduction` 退回本金)**：
   $$S_k = S_{k-1} + \text{shares\_delta} \quad (\text{股數按減資比例減少})$$
   $$C_k = \max(0, C_{k-1} - \text{退回現金總額}) \quad (\text{總成本扣除返還本金})$$
   $$\text{每股平均成本 } P_k = \frac{C_k}{S_k}$$
5. **賣出 (`sell`)**：
   賣出不改變每股平均成本，依現存平均單價等比例扣減總成本：
   $$P_k = P_{k-1}$$
   $$S_k = S_{k-1} - \text{賣出股數}$$
   $$C_k = S_k \times P_k = C_{k-1} - (\text{賣出股數} \times P_{k-1})$$
   同時可計算出該筆賣出的已實現損益：
   $$\text{已實現損益} = (\text{賣出成交金額} - \text{手續費} - \text{證交稅}) - (\text{賣出股數} \times P_{k-1})$$

## 伍、統一發票期別判定與對獎邏輯

### 一、期別自動計算規則
統一發票的期別由 `invoice_date` 決定，不允許任意手動指定。判定演算法如下：
1. 提取開立日期之公曆年份與月份（1 至 12）。
2. 將月份轉換為當期的起始奇數月份：
   $$\text{期別起始月} = \left( \left\lfloor \frac{\text{月份} - 1}{2} \right\rfloor \times 2 \right) + 1$$
3. 格式化為 2 碼字串（補零），與年份拼接。
   - 例一：`2026-02-14` $\rightarrow$ 月份為 2，起始月為 $\lfloor 1/2 \rfloor \times 2 + 1 = 1$，期別為 `2026-01`。
   - 例二：`2026-05-01` $\rightarrow$ 月份為 5，起始月為 $\lfloor 4/2 \rfloor \times 2 + 1 = 5$，期別為 `2026-05`。
   - 例三：`2026-12-31` $\rightarrow$ 月份為 12，起始月為 $\lfloor 11/2 \rfloor \times 2 + 1 = 11$，期別為 `2026-11`。

### 二、開獎與兌獎流程
1. 財政部開獎後，將該期別（`period`）的中獎號碼寫入 `invoice_lottery_draw` 表，關聯對應的 `invoice_prize_rule`（內含獎項代碼與預設獎金）。
2. 對獎查詢時，比對發票後 8 碼、末 7 碼至末 3 碼，找出符合的最高獎項規則 ID。
3. 若發票中獎，更新 `invoice.winning_prize_id`。
4. 當實際領獎並撥入帳戶時，於 `income` 表新增一筆入帳資料，記錄實際收款帳戶、中獎金額，並填入 `income.invoice_id = invoice.id`。資料庫的 `UNIQUE(invoice_id)` 約束確保同一張發票絕無重複入帳中獎獎金之可能。

## 陸、這一次不建的表（明確剔除項目）

為維持本階段系統極簡、穩定與專注，以下在需求中標示為「先不要做」的項目，本設計**嚴格排除、一律不建表**，並載明邊界原因：

1. **預算表 (`budget`, `budget_category_limit`)**：
   - 先不做預算編列、每月限額警告或超支推播，維持單純的事後流水帳記帳。
2. **固定收支 / 週期性排程表 (`recurring_transaction`, `subscription_schedule`)**：
   - 先不建立定期扣款、每期房租水電自動生成的預約排程表，每一筆交易均由實際發生時手動記錄。
3. **載具自動匯入與授權表 (`carrier_credential`, `e_invoice_sync_log`)**：
   - 先不對接財政部「電子發票整合服務平台」API 或手機條碼載具自動爬蟲，不儲存任何載具驗證碼或同步排程。
4. **即時股價與歷史行情表 (`stock_quote`, `market_daily_price`)**：
   - 先不抓取公開市場盤中與收盤報價，不計算未實現損益市值，僅專注於交易歷史紀錄、持有股數與買入成本計算。
5. **銀行同步與 Open Banking 表 (`bank_credential`, `bank_connection_session`)**：
   - 先不串接第三方開放銀行（Open Banking）API，不儲存銀行網銀憑證或交易流水自動下載設定。
6. **複式記帳 / 會計分錄表 (`journal_entry`, `general_ledger_line`)**：
   - 本設計採個人財務直覺的「帳戶餘額單式流水帳」結構，不建立借貸分錄（Debit/Credit）會計科目表，降低個人使用複雜度。
7. **刪除帳務列 / 軟刪除歷程表 (`deleted_audit_log`, `tombstone_record`)**：
   - 需求明確指出先不做「刪除帳務列」，且父列被參照時強制禁止刪除，故不設計軟刪除（Soft Delete）註記欄位與刪除歷程稽核表。
8. **使用者帳號與家庭共享表 (`user_profile`, `family_sharing`, `tenant_member`)**：
   - 本系統定位為個人本機單人專用記帳本，不發明多租戶、使用者帳號系統、權限角色或家庭成員共同記帳表。
